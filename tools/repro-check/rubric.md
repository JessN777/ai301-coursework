# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env-recorded | Repro report environment record (and any version/OS/driver lines in the steps or artifacts), read against the issue's stated target and the repo-facts bug-report asks | The report names enough to place the attempt: the software version under test and the OS/platform. If the issue or template makes a driver, backend, browser, shell, or build profile part of the trigger, that is named too. A log excerpt or command output is not a substitute for an environment record. | required |
| steps-followable | Repro report steps, any linked playground/gist, and whether inputs are actually provided, read against the issue's trigger | A stranger can re-run from the report: starting state, commands or UI actions, and the inputs needed to hit the issue's trigger. Fail if a required input lives only in a private unshared repo/config, or if the steps skip the issue's actual trigger (wrong flag syntax, swapped operator, omitted driver on a driver-specific bug). | required |
| behavior-matches | Output excerpts, logs, screenshots, exit codes, and "actual"/"expected" lines in the repro report, read against the issue body's described behavior | The shown artifact displays the issue's behavior (or, for an honest cannot-reproduce, clearly displays a different outcome). Fail if the artifact is an adjacent failure (graceful arg-validation, compile error from a mutated expression, garbled-but-alive output narrated as a crash), if it only shows the program launching, or if "actual" names a crash/bug the artifact does not show. | required |
| evidence-backs-claim | Claim comment plus repro report claims ("reproduced", "confirmed", "cannot reproduce", root-cause assertions) against the artifacts in the report | Every load-bearing claim is backed by a shown artifact or a named negative result. An evidenced cannot-reproduce passes. Fail me-too comments, "I verified" with no transcript, diagnoses with no run, or an "expected" line that contradicts what the artifact shows. | required |
| env-delta-named | Report environment and version lines versus the issue's confirmed target (latest/main, named version, named OS) | If the tested version or platform differs from the issue's stated target, the report names the difference. Same version, or a named newer-version still-repro, passes. Silent use of an older or off-target environment (especially against a "confirmed on latest/main" issue) fails. | required |
| claim-specific-honest | Candidate claim comment read against the issue title/body | The claim names this issue's specifics (what will be investigated) and promises a report or next investigation step. Fail a +1 with no intent, self-assignment with no concrete plan, or a guaranteed fix / reserved-for-me / calendar promise. | required |
| repo-conventions | Repo-facts contribution / AI / comment policy, plus the claim and repro comments | If the policy requires disclosing AI usage in issues or comments, the comments disclose it (course packages are AI-assisted work). If the policy only requires human-written comments in the author's own words, pass when the comments are specific and human-voiced rather than generic boilerplate. If there is no AI policy, or a permissive "welcome, you are responsible" policy with no disclosure mandate, this check passes. | required |

## Verdict rule

Accept only if every required check is `pass`. Preferred checks never change the verdict. Treat `unclear` on a required check as `fail`: missing proof is not ready to post. In live claim-only mode (no repro report yet), leave every check that needs the repro report out of this rule; accept the claim if `claim-specific-honest` and `repo-conventions` both pass.
